## 已复现的错误

2.1.0 的规划器 `publish()` 每次执行以下过程：

1. 创建一个新的 `RouteMemory`。
2. 用原始完整曲线初始化，内部弧长进度归零。
3. 调用 `valid()`；它只能在已有进度前方2米的窗口内投影当前位置。
4. 无人机已飞到路径中段时，投影误差超过1.2米，于是在检查障碍之前就拒绝。

规划器自己的 `owned_route_` 由里程计持续推进，仍判断旧路线有效并执行 `KEEP_RECOVERY_ROUTE`；跟随器却收到拒绝许可，执行低速恢复、等待，形成相互矛盾的循环。`WAITING_FOR_EXECUTABLE_PATH` 虽唤醒规划器，保留有效路径的分支又让它返回。

用日志中抽样曲线和起始位置，在没有任何障碍的网格上调用真实 `RouteMemory` 复现结果：

| 无人机 | 重置进度后的投影误差 | 整条曲线最近投影误差 | 最近弧长进度 | 重置/保留进度后的验碰结果 |
|---|---:|---:|---:|---|
| scout1 | 5.323米 | 0.621米 | 7.285米 | 拒绝 / 通过 |
| scout2 | 4.944米 | 0.622米 | 6.903米 | 拒绝 / 通过 |

这里的数值来自日志抽样路径，在空地图上用于隔离进度错误，不是对实际占据点云的完整回放。该日志只保存地图计数，没有保存全部体素。

## 修复内容

- 里程计同时推进 `owned_route_` 和实际发布曲线的 `route_`。
- 执行许可复制实际发布曲线的当前状态，不再重新设置曲线、清零进度。
- 异步工作线程返回 `RETAINED_STRAIGHT_ROUTE` 原曲线时，候选验证继承原曲线的当前进度。
- 重新提交原曲线时，路由所有权继承已经通过检查的进度；搜索器接收从当前位置开始的曲线后段。
- 规划状态新增 `published_route_progress` 与 `owned_route_progress`。两者属于各自曲线的弧长坐标；安全前缀截取后原点不同，不能简单要求两个数始终相等。
- 跟随器诊断新增 `px4_armed`、`px4_status_age`、`target_system`、`px4_status_system_id`，便于后续区分多机命令目标和状态来源。

没有将 `valid()` 改为全路径无条件最近点搜索，避免在自交或来回路径中错误跳到远处弧段。当前连接段和未来路段仍逐段检查最新地图及占据保护地图；地图/里程计超时仍拒绝正常跟踪。没有缩小机体硬包络，没有取消声呐或多机保护，也没有新增路径排斥策略。

配置参数值与本次日志中的 `effective_package_config.yaml` 保持一致，包含最高高度6米、起飞高度3米、疏散间距9米和体素0.18米。几何跟踪、网格、A*、B样条四个核心头文件与第二份0.22.1源码保持一致。

## 验证与使用

`tests/v210_node_continuity_test.py` 现在提取真实里程计回调、发布器、工作线程、提交逻辑、占据保护检查和所有权恢复方法，消息传输/时钟使用桩。新增验证覆盖：

- 无障碍直线路径连续飞行超过8米，几何版本不变且许可持续为真；修改前该验证失败。
- 复用与重新提交旧曲线不会归零进度。
- 前方新障碍仍拒绝许可，身后新障碍不会仅因保留过去曲线而否决前向路径。
- 地图过期拒绝许可，恢复新鲜数据后重新验证。

离线测试不包含 ROS节点链接、DDS、PX4或Gazebo运行；仍需要真实仿真验证。本次修复解决已确认的进度退化，不能声称三号机的起飞无响应已经修复。

替换和构建命令见包根目录 `README.md`。运行中的旧节点必须结束后再安装，安装脚本会备份旧构建产物。

运行后重点检查：

```bash
timeout -k 2s 12s ros2 topic echo --once /scout1/planning/status --field data
timeout -k 2s 12s ros2 topic echo --once /scout2/planning/status --field data
timeout -k 2s 12s ros2 topic echo --once /scout3/planning/control_diagnostics --field data
```

对一、二号机，在路线当前连接及前方都通过验碰、输入新鲜时，应看到 `executable=1`。若仍为0，应结合当前理由和新增进度字段分析，不要统一将所有拒绝归因于此缺陷。

三号机仍不起飞时，需要同时核对 PX4接收端的轨迹设定值、实际状态/本地高度、执行器输出与Gazebo模型实际高度。该份日志只有发送端命令和ROS里程计，不能区分接收问题、估计问题、输出问题和模型接触问题。低于 `z_min` 导致规划器报告 `ALTITUDE_OUT_OF_BOUNDS` 是地面未起飞的结果；TAKEOFF分支不以这条路径许可决定爬升。
